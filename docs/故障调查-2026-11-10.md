# 抖音与YouTube故障调查（5.2.3–5.2.4）

- YouTube已定位并修复本机子进程输入继承阻塞，实际安装后的字幕提取已通过；日常Edge取得442条字幕并完成GPT任务，用户已确认正常。
- 抖音5.2.3真实日志持续记录附件0个，实站新组件已确认与旧选择器不匹配；5.2.4适配新组件，完整实站流程仍待验收。
- B站已有字幕可直接交GPT，绕过Native及AI Studio；B站正常不能验证新增跨平台链路。

## YouTube：已确认的根因

- 样本为用户提供的`nAEcMiFmqgg`，时长818秒，平台提供中文人工字幕；已取得442段，末段结束817.517秒。
- [Job.run](../native/host.py)启动子进程时默认继承父进程标准输入；父程序此时在读取Native Messaging输入管道。
- 在本机Windows的真实协议环境中，该继承使子Python尚未执行用户代码就阻塞，字幕子任务90秒超时后又等待45秒元数据解析。
- 最小修复为非交互子工具显式使用`stdin=subprocess.DEVNULL`，不让媒体工具使用浏览器通信输入。
- Python说明见[官方subprocess文档](https://docs.python.org/3/library/subprocess.html#frequently-used-arguments)；具体Windows阻塞结论来自下面的本机单变量实验，未宣称所有系统均会发生。

| 验证条件 | 结果 | 证明范围 |
|---|---|---|
| 已安装程序直接执行字幕命令 | 2.147秒，442段中文 | 字幕组件和该视频可用 |
| 同组件经Native协议后台执行，修复前 | 142.153秒，元数据超时 | 真实后台链路失败 |
| 不联网，仅启动写标记的子Python，继承输入 | 超时，子程序标记未创建 | 排除网络、字幕平台与AI模型 |
| 同一实验，仅隔离子程序输入 | 子程序0.172秒完成 | 复现并消解直接触发条件 |
| 隔离诊断中同一视频，仅改输入 | 7.482秒，442段/818秒 | 修复方向有效 |
| 正常Windows已安装Native5.2.3，经隔离Edge调用 | 10.168秒，442段/818秒，音频与图片均未下载 | 安装入口及真实提取通过，尚非日常GPT交付证明 |

- 不能把字幕API异常、格式错误或超时等同于“视频没有字幕”，旧异常吞没与额外元数据解析会放大等待并遮蔽原因。
- 页面存在字幕轨道也不保证直接fetch轨道地址可用：此次浏览器直接请求返回200但正文为空，而字幕组件完整请求取得442段；因此本版保留成熟字幕组件，不凭轨道存在就改用未经验证的请求。

## 抖音：已确认事实与未知

- 用户历史截图已有提示词和Generated Audio附件，但未Run，并出现任务取消；用户明确否认主动取消、关闭来源或换作品。
- 当前单条旧诊断无法还原该次的附件就绪、Run点击、回执及取消触发顺序；后续某次YouTube记录为来源关闭，也不能反推此前抖音的用户操作。
- [附件确认](../aistudio-content.js)在卡节点替换、播放按钮文案不在匹配表时，存在一直等待的可复现条件；这些来自受控DOM，不足以认定现场使用了该DOM形态。
- 现有抖音播放页媒体提取不携带字幕轨道，字幕优先覆盖不足；但尚未证明当前抖音作品提供可独立取得的字幕，不能把这一缺口直接当此次未Run的原因。
- 接下来的判定依据为本次任务实际日志，而非继续扩大选择器或反复下载同一音频。

## 自动日志与验收遗漏

- [任务诊断](../task-diagnostics.js)在扩展本地存储`vidsiftTaskDiagnostics`，覆盖弹窗打开、运行、来源核对、Native版本/处理阶段、附件状态、Run、转写、目标回执与终态。
- 每条任务使用稳定身份，页面上报需匹配来源/目标标签；保留最近20条任务，每条最多120事件，并有总量限制；连续相同Native进度合并，等待状态按变化或十秒采样。
- 只保存版本、作品编号、耗时、错误/取消分类和有限DOM结构摘要，不保存网址查询串、账号、令牌、提示词、字幕正文、音频或文件名；日志不自动上传。
- 原测试把AI Studio替换为固定HTML，附件直接ready、Run及回复形态预设，因而不能检出真实网站变化；新增日志集成测试也仅证明日志链路，不冒充实站兼容。
- 本版148项扩展测试、48项Native测试及隔离Edge日志接力通过；新增Windows协议回归在旧代码上失败、修复后通过。
- 实际抖音完整发送及日常YouTube到GPT流程仍待验收，不标为完成。

## 5.2.3用户运行后的新证据与5.2.4修复

- YouTube实际任务：9.840秒取得442条中文字幕、818秒视频信息，28.490秒目标确认并完成；没有下载音频，用户明确反馈已可用。
- 抖音实际作品7690971395077764273长1956.978秒，44.127秒取得音频、47.409秒进入AI Studio；附件显示62,574 tokens，但日志连续数分钟cardCount=0、Run可用、未进入Run点击。
- AI Studio实站官方媒体样例DOM为ms-prompt-media内data-test-id=prompt-media-container，包含ms-token-status内token-count及Remove media控件；旧选择器命中0，新组件有1个，因此直接等待原因已确认。
- 5.2.4仅在新组件内正数token处理回执、可用移除控件且无busy/error时确认附件，旧组件继续原有规则；不把全页token数或Run可用单独当上传成功。
- 正常Windows隔离公开页复核同一抖音作品：仅一条完整独立播放音轨，47,341,751字节，193530 bps，三个URL是同文件镜像；未发现更小候选，不能宣称下载缩小十倍。
- 页面现有caption字段为69字符字符串，未证明是带时间戳字幕；未取得字幕轨道保持unknown，不能将未提取说成平台无字幕。
- 汇总同作品候选并保留镜像修复了选择缺口；下载/上传字节分开记录，只有真实下载下降才认定下载提速，不用编码后体积替代。
- 只有有效字幕能省去转写阶段；没有取得字幕时仍需音频转写，额外AI Studio阶段本身不是流程错误，但应后台运行并自动完成SRT到GPT接力。
